# VolgaAsk DocumentGenerator

Приложение на Python 3.11+ для заполнения опубликованных бланков Волгатеха. Шаблоны, компоненты и вопросы хранятся в PostgreSQL. Для поиска по смыслу и разбора свободных ответов используется локальная Ollama.

## Запуск в PowerShell

Из корня VolgaAsk можно запустить генератор вместе с его базой и локальной моделью, а затем открыть диалог в терминале.

```powershell
docker compose up -d --build generator
docker compose exec generator python -m document_generator.cli
```

При запуске CLI на хосте установите пакет и задайте `TEMPLATE_DSN`, `PGPASSWORD`, `OLLAMA_HOST`, `OLLAMA_MODEL` и `DOCUMENT_OUTPUT_DIR` в `.env` по образцу `.env.example`. CLI использует тот же каталог, который инициализирует сервис генератора.

## Заполнение заявления

1. Напиши «Хочу оформить материалку». Можно сразу добавить часть данных или все данные одним сообщением. Если предложено несколько бланков, укажи номер.
2. Подтверди выбор словом «да». Ответ «нет» возвращает к выбору заявления.
3. Отвечай на вопросы. В одном сообщении можно указать несколько полей, например «Группа ИВТ-241, факультет ФИиВТ». Для исправления назови поле и новое значение.
4. Проверь сводку. Здесь можно добавить необязательные сведения или изменить дату. После каждой правки приложение покажет сводку снова.
5. Напиши «подтверждаю». Приложение выведет путь к DOCX. До создания файла диалог можно завершить словом «отмена».

## Использование из Python

```python
from document_generator import DocumentGenerator

generator = DocumentGenerator()
session = generator.start("Хочу заявление на возврат денег")
print(session.message)
```

Передавай `session.id` в методы одного экземпляра сервиса. `send_message(id, text)` возвращает снимок с полями `state`, `message`, `values` и `output_path`. Сессии хранятся в памяти процесса.

| Метод | Назначение |
| --- | --- |
| `get_suggested_template(id)` | Получить сведения о выбранном бланке |
| `confirm_template(id, accepted)` | Принять или отклонить предложенный документ |
| `get_state(id)` | Получить текущий снимок диалога |
| `is_ready(id)` | Проверить, что данные собраны и доступны для просмотра |
| `generate(id)` | Подтвердить просмотренную сводку и получить путь к DOCX |
| `cancel(id)` | Завершить сессию с отменой |

Вызов `generate` служит явным подтверждением пользователя. После успешной генерации повторный вызов возвращает тот же путь. Ошибки прямых команд фасада доступны как `document_generator.errors.DocumentError`. Диалоговые методы `start` и `send_message` передают сообщения об ошибках в `session.message`.

## Шаблоны

При первом запуске API переносит прежние DOCX и поля из `schema.json` в таблицы `form_templates`, `form_versions`, `form_components` и `form_template_components`. Новые версии сотрудники собирают в разделе «Управление документами → Шаблоны документов». Сохранённая версия доступна новым диалогам сразу. Начатые заявления продолжают использовать выбранную версию. Одинаковый компонент может встречаться в нескольких местах бланка, заявитель вводит его значение один раз.

Вместо Ollama можно передать в `DocumentGenerator(provider=...)` реализацию `BaseLLMProvider` с методом `request_json`.
