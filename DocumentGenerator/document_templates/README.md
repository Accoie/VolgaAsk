# VolgaAsk — DOCX-шаблоны Document Generator

Создано на основе пяти исходных бланков ПГТУ, предоставленных пользователем. Это **технические шаблоны для прототипа**, не утверждённые университетом новые бланки.

## Состав

Каждая директория содержит `template.docx` (исходный бланк с маркерами `{{ field }}`) и `schema.json` (описание документа, алиасы, поля и вопросы для DG).

## Работа DG

1. Найти существующий документ по `title`/`aliases` или подобрать вариант LLM среди пяти известных `id`.
2. Предложить пользователю найденный вариант и дождаться подтверждения.
3. Загрузить `schema.json` и собрать `fields` (не повторять уже заполненные поля).
4. Проверить обязательные значения и показать пользователю для подтверждения.
5. Передать словарь ключей в `docxtpl.DocxTemplate(...).render(context)`, затем сохранить `.docx`.

Дата в прототипе отображается в виде `DD.MM.YYYY`. Для форм с печатным шаблоном даты исходный формат строки немного упрощён. Статус `required` — техническое требование DG для проверки заполненности, а не юридическое утверждение об обязательности информации.

## Важно

- Исходный текст бланков сохранён по смыслу; в областях заполнения заменены линии подчёркивания на маркеры. Часть макета формы адаптирована для автоматического заполнения. Сверьте распечатанный результат с действующим официальным бланком.
- В исходниках указан «И.о. ректора ФГБОУ ВО «ПГТУ» Роженцову А.А.» — в прототипе это оставлено **без изменений**. Перед использованием обязательно уточнить актуального адресата и бланки.
- Подписи заявителя, старосты, профорга, специалистов и поля регистрации не генерируются. DG не одобряет и не подаёт заявление.
- Некоторые текстовые поля грамматически зависят от предлога (например, «в связи с», «Прошу считать меня»): LLM должна предложить формулировку, а пользователь подтвердить итоговый DOCX.
- В текстовом бланке на возврат денежных средств банковские реквизиты и выписка перечислены как приложения. Они не являются отдельными полями для внесения в текст.
- `schema.json` — проект контракта MVP. Названия и правила проверки можно уточнить после реализации `TemplateRegistry`/`DialogManager`.
